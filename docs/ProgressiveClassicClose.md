# Асинхронное закрытие progressive-графа Classic

SDK 1.13. Только FoxicMP Classic; YouTubeHarvester не изменялся.
Qt сохраняет [native retirement SDK 1.12](ProgressiveEngineShutdown.md).

## Область действия

Новый путь применяется к progressive-сеансу, граф которого создан штатным
STA-потоком Classic. Это published API v1/v2 и legacy/provider при включённой
пользователем worker-thread opening. Настройка профиля не меняется.
Обычные источники и графы, созданные в UI-потоке, сохраняют прежнее закрытие.
Это конкретная граница: всё закрытие Classic не объявляется асинхронным.

При Stop/Close источник получает Cancel, а UI возвращает управление без ожидания
завершения открытия или уничтожения такого графа. Нативные фильтры освобождаются
в прежнем STA, с прежним порядком Release. Поток не отсоединяется от CMainFrame.
Окно и дочерние render-окна живут до сигнала фактического окончания CloseMediaPrivate.

## Состояния и владение

1. При незавершённом открытии выставляется abort; UI опрашивает событие окончания
   неблокирующей проверкой. Поздний WM_POSTOPEN потребляется без применения.
2. После окончания открытия STA получает TM_CLOSE. UI продолжает обычный message
   loop; его graph polling, renderer callbacks и команды к закрываемому графу
   временно отключены. Stop, Close, выход и безопасные запросы открытия доступны.
3. Только реальный close event разрешает окончательную UI-очистку. Новое открытие
   или выход выполняются после неё. Timeout не подменяет событие завершения.

Ожидает максимум одно открытие или одна owned командная строка. Новое намерение
заменяет прежнее; Stop/Close отменяет его. Prepared Source хранится в отложенном
OpenFileData, затем передаётся текущему графу. В сохранённом m_lastOMD не остаётся
лишней ссылки, удерживающей медиафайлы после закрытия.

IPC status для ожидающего источника возвращает buffering с нулевой позицией,
не читая изменяемые поля старого графа. Reader-команды работают с фактическим
владельцем ожидающего источника; квитанция старого reader остаётся независимой.
После принятого Cancel обычный start без replace допускается и ждёт закрытия
старого графа. Уже принятый новый pending start считается активным: для его замены
по-прежнему требуется replace=true, иначе возвращается session_busy.
После запроса выхода новые IPC-запросы получают player_closing. Повторный Close
не запускает вложенное ожидание, повторный выход не создаёт поток WM_CLOSE.

В capabilities добавлены поля graphShutdown:

```json
{
  "progressiveStaCloseAsync": true,
  "deferredStart": true,
  "deferredExit": true,
  "maxPendingStarts": 1,
  "uiOwnedGraphCloseAsync": false
}
```

Прежние поля сохраняются. nativeTeardownDetached=false: CMainFrame остаётся
владельцем жизненного цикла. fullInputPump=false не обещает безусловно выполнять
любые команды внутри прежнего синхронного graph wait; для нового progressive
пути используется обычный UI loop с указанными ограничениями команд.

## Release и ограничения

Источник старого графа удерживается до завершения его очистки. Исчезновение
окна, Stop или принятие нового start не являются подтверждением filesClosed.
Плеер подтверждает reader release только после реального закрытия файлов.

Если native фильтр не завершает работу, окно и владение сохраняются; предельное
время всего teardown не обещается. Cancel прекращает дальнейшее чтение Source,
но не является измерением немедленной тишины в аппаратных аудиобуферах.
Внешнее завершение процесса/сеанса ОС по-прежнему требует PID/birth recovery.
Физическое оборудование, Wayland и дополнительные кодеки не добавлены в проверку.
