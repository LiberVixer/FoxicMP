# Ошибки необязательных SRT — SDK 1.24

Общий schema-2 медиаслой Classic, Windows Qt и Linux Qt изолирует ошибки
optional UTF-8 SRT от обязательных аудио/видео. YouTubeHarvester не изменяется.
Capabilities фактического EXE: `schema2Playback.subtitles.optionalErrorIsolation`
и `retainsValidatedCopyOnSourceError`.

## Состояние дорожки

`subtitleTracks` сохраняет id/label/language/path/ready/default/forced. Добавлены
`state`, `errorCode`, `error`; ошибки SRT не переносятся в корневой `error` A/V:

| state | ready | Значение |
|---|---|---|
| waiting | false | Файл ещё не завершён; A/V не задерживается |
| ready | true | Приватная копия подготовлена и проверена |
| error | false | Копию получить не удалось; дорожка не подключается |
| cached | true | Оригинал повреждён после проверки; сохранена прежняя проверенная копия |

`ready` сообщает об успешной подготовке проверенной копии; `loaded` — фактическое подключение
декодером в активном status. При отказе backend добавляются
`backendErrorCode:decoder_error` и `backendError`; видео продолжает работать.
Classic не повторяет неудачную загрузку каждый тик. Qt связывает асинхронный
ответ sub-add с текущим источником: отменённый ответ старого источника не
становится фатальной ошибкой нового видео.

Валидные SRT продолжают подключаться после отказа другого SRT. Qt восстанавливает
выбор по пути проверенной копии, поскольку после пропуска повреждённой дорожки
числовой sid может измениться. Если выбранная копия больше не загружается,
субтитры отключаются, а перемотка и A/V продолжаются.

## Границы изоляции

Изолируются ошибки UTF-8/таймкодов/размера, отсутствующий завершённый файл,
небезопасный или испорченный optional ресурс, отказ локального чтения/создания
копии, failed/cancelled/retired optional SRT и отказ её загрузки декодером.
Пределы SRT, локальные пути, проверка владельца, запрет ссылок и подтверждённые
диапазоны сохранены. Неправильные метаданные, смена идентичности и отзыв
подтверждённых диапазонов по-прежнему отвергаются целиком. Required subtitle
и неподдержанный контейнер остаются вне объявленного медиапрофиля.

Обычный ResourceSource по умолчанию строгий. Медиамост включает изоляцию явно,
только если ресурс используется исключительно optional SRT. Ссылки из required
дорожек, initialization и segments не изолируются. Ошибки обязательных
аудио/видео и всего writer остаются фатальными для A/V.

Ошибка опубликованного файла сохраняется до нового открытия/поколения либо
новой дорожки с новым resource ID. Автоматической подмены неизменяемых байтов нет.
Проверенная приватная копия не обновляется из повреждённого оригинала.
Дескрипторы и квитанции остаются консервативными до закрытия Source; исходники
удаляются только после released/filesClosed всех читателей.

## Проверка

[Результаты трёх редакций](ProgressiveOptionalSrtValidation-2026-10-29.md).
CTest Qt: `progressive-optional-srt`, генератор обычных медиа прежний.
Classic: `tests/windows/progressive_family_test.py --subtitle-only` в отдельной
копии с выключенной регистрацией контекстного меню. Это player-only стенд;
реальный Harvester, физическая задержка аудио, большие файлы, live/segments
и optional audio этим этапом не квалифицируются.
