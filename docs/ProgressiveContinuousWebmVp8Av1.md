# Непрерывное воспроизведение WebM VP8 и AV1

Linux Qt, Windows Qt и Windows Classic используют один рабочий процесс
для чтения растущего WebM. Он копирует кодированные пакеты в приватный поток
плеера, проверяя границы чтения по опубликованному префиксу с SHA‑256.

Клиент выбирает один из четырёх режимов `continuousRemuxStart.mode`.

| Видео | Без звука | Звук Opus |
|---|---|---|
| VP8 | `continuous-webm-vp8-video-v1` | `continuous-webm-vp8-opus-v1` |
| AV1 | `continuous-webm-av1-video-v1` | `continuous-webm-av1-opus-v1` |

Проверка возможностей выполняется запросом
`{"version":1,"action":"continuousWebmCapabilities"}`. Базовый ответ
`capabilities` сохраняет прежний размер. SDK 1.109 поддерживает эти режимы
через `ContinuousRemux`. Сценарием управляют прежние команды публикации,
воспроизведения, перемотки и освобождения ресурса.

В schema 2 укажите `containerHint: "webm"` и явный `codecHint` каждой дорожки.
Все дорожки ссылаются на один локальный файл известной длины.
`timeline.duration` задаёт конечную точку **видео** с точностью до миллисекунды
в стандартной шкале 100 нс. Первый видеокадр начинается с нуля. Плеер
вычисляет число кадров и сэмплов Opus из блоков. Поля `videoSamples`,
`videoRate` и `audioSamples` для этих режимов не используются.

Поддерживаются известный и неизвестный размер Segment, конечные и
неопределённые по размеру Cluster, переменные интервалы между кадрами в
шкале 1 мс. Для `SimpleBlock` длительность берётся из следующей временной
метки и объявленного конца видео. В `BlockGroup` требуется явный
`BlockDuration`. Пакеты Opus mono/stereo в 48 кГц сохраняют pre-skip и
`DiscardPadding`. [Спецификация Matroska](https://www.rfc-editor.org/rfc/rfc9559.html)

VP8 ограничен отображаемыми кадрами с постоянной геометрией, AV1 —
Main 8/10 бит, 4:2:0, с одним отображаемым кадром на пакет и неизменной
конфигурацией. Пределы составляют 128 МиБ входа, 64 МиБ выхода, 1 МиБ
заголовка, 16 МиБ на кластер и 50 000 пакетов. Шифрование, lacing,
перестановка пакетов, смена конфигурации и дополнительные дорожки выходят
за рамки этого режима.

Скрипт `tests/progressive_continuous_webm_video_test.py` создаёт
синтетические образцы, проверяет рабочий процесс и открывает их через
обычный API плеера. Linux-прогоны запускаются с частным X11, D‑Bus и
PulseAudio через `qt/tests/run_tests.sh`. Для CTest передайте путь к
подготовленным образцам в `FOXICMP_TEST_CONTINUOUS_WEBM_CORPUS`.

```bash
PYTHONPATH=qt/tools python3 tests/progressive_continuous_webm_video_test.py \
  --prepare --corpus /tmp/foxicmp-webm-corpus
```
