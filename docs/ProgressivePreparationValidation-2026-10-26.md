`111bd89ec787263960cf5c9399107963e2a8c12d`. [Машинный отчёт](ProgressivePreparationValidation-2026-10-26.json)
содержит SHA-256 сборок, ответы v2 playback, реальные Classic UI timings и статусы установки.

## Проверки

| Редакция | Regression | Финальная проверка | Exit |
|---|---|---|---:|
| Linux Qt | 5 CTest-групп, 29 QtTest результатов API | 13 результатов preparation (11 сценариев + init/cleanup), отдельный v2 playback | 0 |
| Windows Qt | 6 CTest-групп, 30 QtTest результатов API | Те же 13 preparation и v2 playback | 0 |
| Classic | v2 validate, readers, 11 resource checks с активным v1, 100 RPC, прежний SDK writer, v2 playback и подготовка | Реальный UI: probe+Close, start+Stop во время native disk indexing | 0 |

В финальной Qt-сборке добавлены ещё два сценария после полного regression:
исключение рабочего потока с последующим успешным retry и истечение пятисекундного
response deadline без позднего запуска. Они прошли отдельно на обеих ОС.
Qt UI/audio использует отдельные X11/D-Bus/PulseAudio; Windows Qt — отдельные профили.

`mediaPreparationKeepsUiResponsive` управляет private test gate в реальном рабочем
потоке API, а не подменяет транспорт. Пока поток ожидает:

- Таймер UI продолжает работать; capabilities отвечает через отдельное соединение.
- Второй probe/start получает preparation_busy.
- Для probe и start отдельно проверяются успешное завершение, Close, Stop и disconnect.
- После отмены нет активного progressive-источника.
- Удаление API при заблокированном worker занимает менее 200 мс на стенде.
- Ошибка worker сохраняет ok=false и освобождает слот; следующий probe работает.
- Пятисекундный deadline закрывает соединение; снятие gate позднее не запускает видео.

Для Classic проверяется настоящее окно через SendMessageTimeout(WM_NULL).
Во входной fMP4 вставлены 100000 корректных free atoms; тест ждёт прироста
GetProcessIoCounters минимум на 500 чтений, затем отправляет UI-pings и Close/Stop.
Каждая операция выполнила **100038** чтений, UI ответил на все шесть ping.
Максимальное измеренное ожидание ответа: **0.3541 мс** на этом стенде.
Probe+Close и start+Stop возвращают preparation_cancelled; активного просмотра нет.
Одна закрытая квитанция отменённого start найдена через readers, проверена
readerRelease и удалена через readerForget. Пустой список читателей подтверждён.
Это проверка обработки оконных сообщений; она не является универсальной оценкой
задержки интерфейса под любой нагрузкой или на другом диске.

Обе Qt-редакции после окончательной сборки повторно прошли реальное v2 playback:
10 секунд из двух физически недокачанных файлов, rename+append, complete, natural
finished и files-closed receipt. В Classic этот же сценарий прошёл в полном regression;
после финальной обработки ошибки запуска thread повторён целевой UI/отмена тест.
SHA-256 его отдельной копии совпадает с финальным собранным Classic EXE.

Python SDK: 32 теста, exit 0; семейный контракт: 2, exit 0.
Classic запускался в отдельной копии с ContextMenuPrompted=1 и ContextMenuEnabled=0,
без открытия страницы Formats. Процесс завершён с 0, HKCU команды/иконки совпали
до/после; одноразовая задача удалена, LastTaskResult=0.

## Исправленные промежуточные ошибки

- Фокусный тест сначала запустился из старого EXE без новых функций (exit 8).
- Test helper формировал неверный probe-запрос; исправлены поля, обе системы
  пересобраны и повторно прошли проверки (неуспешные CTest exit 8).
- Параллельная линковка запущенного тестового EXE дала Text file busy (exit 1);
  сборка и запуск сериализованы. Копирование Classic во время линковки также
  завершилось exit 1; после сборки создана свежая изолированная копия.
- Реальный Classic-тест выявил недоступность Close, пока ещё нет фильма (exit 1).
  Close и Stop разрешены во время подготовки; финальный UI-тест обеих команд прошёл.

Эти ошибки не считаются успешными прогонами; в таблице приведены повторные
проверки после исправлений. В JSON сохранены причины и exit codes.

## Установка и границы

Проверенный Linux EXE заменён атомарно, предыдущая версия сохранена для отката.
SHA-256 нового EXE: `3ec096941cdc062a3f488e2708d60cf08a1ee34bdba71d6e0c8c0aa6911d4459`.
INI до/после: `ac9387b8d09f63317ed8ea3b681abad96e5abe8890400d4db6540017e3acde75`.
Профиль, личные файлы и текущий просмотр не изменялись. Проверены --version
(0.2.0) и mediaPreparation в --progressive-api-info установленного EXE.
SDK и исходники этого этапа не обновляют опубликованные установщики 0.2.0.

Проверен первичный IPC probe/start; update/complete, legacy/provider,
последующая индексация, mutex фонового I/O и все status/close пути ещё требуют
отдельной работы. Native disk open/read не прерывается принудительно; тест
удаления API проверяет отсутствие join с UI, а не мгновенное закрытие любых handles.
Новые форматы/live и полная integrity-модель не реализованы. Оборудование/Wayland,
физический звук, длительный drift и реальный Harvester не проверялись этим этапом.
