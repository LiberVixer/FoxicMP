FoxicMP Qt Linux 0.1.24 — внешнее аудио и второй выход, часть пункта 14
Дата: 15 октября 2026, Europe/Moscow. Ветка codex/linux-qt.

Результат
Ctrl+Alt+A → «Звук — файлы и выходы», также в общих настройках.
Автопоиск no/exact/fuzzy/all, до 32 папок по одной в строке, расширения;
native/external/internal приоритет. По умолчанию no/native.
Пути передаются native list, двоеточия/кириллица не разделяются.
Ручной и запомненный выбор важнее приоритета. Повторное открытие/восстановление
уже загруженного файла выбирает его без дубликата. Изменение поиска добавляет
новые дорожки без удаления старых. Live/progressive автопоиск выключен;
в progressive приоритет не вмешивается в состав сессии. Cancel не сохраняет.

Два выхода
Один декодер libmpv, дублирование PCM через временный module-combine-sink
PulseAudio/PipeWire. Два разных pulse/ устройства, основной auto допускается.
Нужны python3, pactl/pulseaudio-utils и helpers/audio_output.py рядом с бинарным
файлом. По умолчанию выключено. Нельзя выбрать собственный временный маршрут,
он скрыт из списков. Системный default sink и громкость других программ
не меняются. При потере выхода — основной, при возврате — повторное подключение.
Проверка доступности каждые 2 с. Смена может кратко прервать звук.

Время жизни и владение
Помощник получает stdin-канал плеера. При обычном закрытии/обрыве/гибели
родителя EOF запускает очистку. Удаление проверяет numeric ID, тип модуля
и уникальное имя; чужой ID после рестарта не удаляется. pactl 16 JSON не
содержит module index, поэтому проверяется таблица list short modules.
Тесты проверяют EOF, убийство родителя, destructor, быстрое on/off/on,
одинаковые устройства, потерю/возврат. Сам помощник не должен быть убит
принудительно до cleanup. Длительная ошибка сервера может помешать очистке;
рестарт сервера удаляет временные модули. Глобальные конфиги не пишутся.

Проверки

20/20 CTest requested OpenGL — 397.87 с, фактически Software fallback.
AudioRoutingTest: 8 passed, 0 failed, 0 skipped в каждом режиме.
Helper unit tests: 4 passed в каждом режиме: валидация имён, владение при
повторном numeric ID, отсутствующие/одинаковые устройства, восстановление.
Реальная среда PulseAudio on PipeWire 1.0.5. Два отдельных null sink,
захват только их мониторов через parec float32le 48kHz stereo, не микрофона.
Обычные настройки parec не выдавали данные до конца короткого замера;
в тесте заданы latency=20ms/process=10ms. После возврата устройства проверка
ждёт установившегося сигнала, а не только статуса готовности. Исходный 8-секундный
ролик достигал EOF при переключении, и QTRY с блокирующим захватом выходил
за ожидаемое время. Тест использует 30-секундный ролик, явно проверяет запас
до конца файла и ограничивает захват 8 секундами по монотонным часам.
Переключение непосредственно у EOF отдельно не подтверждено. Режим exact
распознаёт языковые суффиксы .rus.flac; all добавляет и unrelated.wav,
а выключение поиска после повторного открытия оставляет только встроенный звук. Пиксельные/сэмпловые результаты
старых наборов сохранены. RMS измерения:

Пределы
Физические Bluetooth/USB/HDMI, точность синхронизации/A/V с двумя выходами
ещё не проверены. Native PulseAudio отдельно не испытывался. Это одинаковый
PCM, без отдельной дорожки/задержки/громкости второго выхода, без bitstream
и двух прямых ALSA-выходов. Остались редактор FFmpeg-фильтров/пресеты,
форматы PCM и bitstream/декодер. Пункт 14 пока не завершён.
