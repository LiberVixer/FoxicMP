# Поздние главы и metadata — SDK 1.26, исправления UI в SDK 1.27

Schema 2 может передавать необязательный объект `metadata`:

```json
{"revision":"2","title":"Название","chapters":[
  {"id":"intro","time":"0","title":"Введение"},
  {"id":"main","time":"50000000","title":"Основная часть"}
]}
```

`revision` монотонно увеличивается, `time` задан в единицах общей шкалы 100 ns.
Главы упорядочены, имеют уникальные идентификаторы и находятся в пределах
известной длительности. Допускается до 128 глав; пустой title разрешён.
Обновление metadata не меняет ресурсы, дорожки или декодер.

Linux Qt и Windows Qt обновляют меню глав и маркеры timeline
во время просмотра. Classic обновляет `IDSMChapterBag` и штатное меню глав,
сохраняя его переводы и клавиши. Невалидная metadata отклоняется целиком,
текущий snapshot продолжает работать. YouTubeHarvester не меняется.

Обложки, главы HLS/DASH, live window и embedded container metadata остаются
отдельными этапами.

## Полная замена и фактическое применение (SDK 1.27)

Объект metadata — полный снимок своей revision. `chapters:[]` удаляет
опубликованные главы. При отсутствии chapters Qt возвращается к списку
контейнера (в текущем отдельном fMP4/WebM-профиле он пуст), Classic очищает
свой bag. После удаления/очистки title используется название из start-запроса,
затем обычное имя источника. Пользовательский режим заголовка окна сохраняется.
Новый сеанс начинает собственный отсчёт metadata revision.

Активный status добавляет `appliedMetadata`: revision, title и массив
chapters с time/title. Это фактический UI-список Qt/Classic, а не повтор
принятого объекта metadata. Пока UI не применил revision, значения могут
отличаться. Title и время главы не используются как команды или шаблоны.
Qt сохраняет опубликованный список при событиях chapter-list и повторном
открытии декодера для перемотки; команда главы соблюдает доступный диапазон.
Изменения metadata не записывают пользовательский профиль.
