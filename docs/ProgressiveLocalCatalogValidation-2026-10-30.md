# Проверка локальных страниц каталога — 30 октября 2026

Проверен [адаптер локальных страниц](ProgressiveLocalCatalog.md).
[Машинный отчёт](ProgressiveLocalCatalogValidation-2026-10-30.json) содержит
сценарии, SHA исходников и точные exit codes, включая неудачные попытки.

| Среда | Новые файловые сценарии | Итог |
|---|---:|---|
| Linux, GCC | 25, без SKIP | exit 0 |
| Windows, MinGW GCC | 24, без SKIP | повторный CTest 1/1, exit 0 |
| Windows, MSVC x64 | те же 24, без SKIP | native runner, exit 0 |

Разница — FIFO, проверенный только на Linux. Отчёты MinGW и MSVC совпали.
Проверены реальные файлы страниц в отдельных временных каталогах:

- Каталог на 8192 ресурса без открытия медиа, страница ровно 64 KiB,
  несовпадение физической длины и SHA-256.
- Новая отсутствующая страница даёт `waiting-index`, удаление уже принятой —
  `missing-index`. Подмена файла даже идентичными байтами — `source-replaced`.
- Hard links, file symlinks и связанные/reparse каталоги отвергаются на обеих ОС.
  Папка вместо файла отклоняется с фактическим кодом соответствующей ОС.
- Привязки и модель не изменяются после ошибочного update; исправленная новая
  страница может быть принята. Отмена до/во время большого чтения сохраняет
  прежнюю модель.
- После прогрева API число handles не растёт на 30 публикациях и 15 циклах
  создания/закрытия владельца. Переименование папки не перенаправляет reader
  в другую папку.

Регрессии Linux: модель 90, сегменты 11, модель каталога 51, ResourceSource 30,
integrity 10; CTest 6/6, exit 0. На Windows модель 90, сегменты 11, каталог 51,
ResourceSource 28 и integrity 10 прошли в общем прогоне; новый I/O-тест затем
повторён отдельно после исправления его ожиданий.

Первые Windows-попытки: CTest exit 8, MSVC Python exit 1. Тест считал handles до
первой инициализации Windows API, затем предполагал Linux-код ошибки для папки
вместо файла. Проверка handles перенесена после прогрева и дополнена повторными
циклами владельца; классификация ошибок учитывает реальное поведение ОС.
Адаптер не изменялся ради этих двух различий. Старые результаты не скрыты
обозначением общего прогона Windows как exit 0.

Это не playback-тест: медиафайлы не декодируются, большие media reader leases
не проверены. В существующих регрессионных тестах ResourceSource проверяется
его прежний lease-контракт; это не доказательство готовности leases нового
большого каталога. Отмена не доказывает прерывание зависшего syscall.

Окна плееров, HKCU и пользовательский аудиосеанс не использовались. Harvester,
Windows-установки и профили не менялись. Установленный Linux EXE сохраняет SHA
проверенной сборки SDK 1.36; замены не было. Capability нового каталога и новый
SDK-релиз не публикуются до интеграции и реальных A/V-проверок.
