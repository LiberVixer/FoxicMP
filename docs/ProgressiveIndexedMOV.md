# Воспроизведение MOV во время загрузки

Формат QuickTime MOV с брендом `qt  `, одним `mdat` и одной видеодорожкой.
Поддерживаются H.264 (`avc1`), HEVC (`hvc1` или `hev1`) и MPEG-4 Part 2
(`mp4v`), в том числе в паре с одной дорожкой AAC-LC (`mp4a`).
Индекс `moov` может находиться перед данными или после них. Для хвостового
индекса необходим отдельный подтверждённый диапазон. До его публикации
плеер возвращает `waiting-index`.

Клиент проверяет поддержку через запрос
`{"version":1,"action":"indexedMovCapabilities"}`.
Ответ о возможностях MOV вынесен отдельно, чтобы существующий ответ
обнаружения API по-прежнему укладывался в 64 КиБ. Версия протокола прежняя.

В сеансе schema 2 укажите `containerHint: "mov"` и явный `codecHint`
каждой дорожки. Обе дорожки ссылаются на один локальный ресурс с известной
длиной. Используйте SHA-256 и подтверждённый непрерывный префикс, при
необходимости дополненный одним диапазоном метаданных. Требуется конечная
длительность и нулевой общий сдвиг. Пределы составляют 1 МиБ метаданных,
250 000 сэмплов на дорожку и 16 МиБ на добавление к префиксу.

Плеер читает таблицы сэмплов MOV и строит виртуальные представления для
своих декодеров. Он сохраняет исходные кодированные пакеты и таблицы
времени, включая поддерживаемые `elst` с единичной скоростью. Обёртка
QuickTime `wave` преобразуется в описание AAC для MP4, при этом байты
AAC остаются исходными. Внешние ссылки, шифрование, несколько описаний
одной дорожки, произвольные монтажные списки и другие кодеки находятся
вне этого профиля.

Синтетические образцы и проверки воспроизводятся скриптом
`tests/progressive_indexed_mov_test.py`: `--prepare --corpus DIR` создаёт
корпус, `--runner` проверяет проекцию, `--player` открывает обычный плеер,
а `--controls` запускает тест управления Qt. Для Linux приложение и
звуковой выход проверяются через изолированный запуск `qt/tests/run_tests.sh`.
