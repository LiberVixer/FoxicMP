# FoxiqMP qt 0.1.72: звук и OSD

Проверка 24 октября 2026 года.

## Причина отсутствия звука

У установленного Linux-плеера `audio/mute=false`, громкость 72%, выход `auto`.
Выход PipeWire не был заглушён, но отдельный поток FoxiqMP qt имел `Mute: yes`.
Отключение mute только для этого потока восстановило звук; пользователь это
подтвердил. Доказательств ошибки декодирования или связи mute с прежними
тестами нет. Общая громкость и выход рабочего стола не изменялись.

## Изменения

- Qt: новый профиль и все места чтения отсутствующего `ui/osd` используют `false`.
  Сохранённые `true`/`false` не перезаписываются.
- Windows Classic: резервное значение `ShowOSD.Enable` также равно нулю;
  поставляемый шаблон уже содержал `ShowOSD=0`.
- Linux: явно заданный `PULSE_SINK` выбирает PulseAudio backend libmpv,
  поскольку нативный PipeWire его не использует. Без этой переменной остаётся
  обычный автоматический выбор; явные startup options имеют приоритет.
- Основной тестовый runner создаёт отдельные D-Bus, X11 и PulseAudio с null sink.
  В тестовом сервере не загружаются обнаружение оборудования и stream-restore;
  настройки потоков рабочего стола не используются. Сервер и сокет удаляются
  при завершении. Дополнительная зависимость runner: пакет `pulseaudio`.
- Проверка аудиомаршрута подтверждает фактический backend, принадлежность потока
  нужному sink и ненулевой RMS записи с его monitor. Тест отрисовки OSD явно
  включает эту функцию.

## Проверки

Windows Qt: нативная сборка 0.1.72, 20/20 проверок, процесс завершился кодом 0.
Тесты запускались из установленной папки с системным PATH, без SDK в PATH.
Содержимое установленного INI до/после совпадает; временная задача запуска
и тестовые файлы удалены.

Windows Classic: сборка с новым резервным значением успешна. Работающий
у пользователя Classic не останавливался, установленный EXE не заменялся.
Изменение включено в исходники и собранный дистрибутив.

Linux: appearance, audio-routing, window-title, audio-processing и audio-encoding
успешны. В audio-routing проверены PulseAudio backend, точный sink
и ненулевой аудиосигнал с monitor; явный `ao=pcm` в обработке/кодировании
сохраняет приоритет. После обновления сценария настроек для нового начального состояния OSD
группа player также прошла (88,12 с). Все шесть затронутых Linux-групп успешны.
В Linux проверены как выключенное начальное состояние галочки OSD, так и
её включение через настройки с появлением сообщения.

Установленная Linux-версия обновлена до 0.1.72; исполняемый файл совпадает с проверенной
сборкой, содержимое INI до/после замены совпадает. Windows Qt также установлена
как 0.1.72. Рабочий стол сохранил исходный физический выход и `Mute: no`,
после тестов в нём нет временных тестовых sink.
