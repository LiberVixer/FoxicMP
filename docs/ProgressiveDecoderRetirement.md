# Continuous playback: освобождение файлов без ожидания close callback

5 ноября 2026, приложение 0.2.0, SDK 1.82.

Исправлена зависимость очистки кэша от времени жизни libmpv callback. После
отмены источника фоновый контроллер закрывает native files декодерных readers,
даже если libmpv пока удерживает объект cursor. Обычный UI Stop остаётся
асинхронным; его выполнение больше не требуется для закрытия этих файлов.

[Измерения, SHA, исходный отказ и точные exit codes](ProgressiveDecoderRetirementValidation-2026-11-05.json).

## Что удалось доказать

Исторический Linux timeout >2 s не содержал подробного release trace. Его точная
причина по-прежнему неизвестна; этот отчёт не объявляет новый тест восстановлением
того старого сеанса.

Отдельный native-тест намеренно удерживает `StreamDecoderCursor` после истечения
heartbeat и не вызывает UI Stop или mpv close callback. На прежнем контроллере
исходник закрывался, но через две секунды оставались `released=false` и
`cleanupCode=cache-in-use`; тест завершился exit 1. Деструктор cursor немедленно
снимал удержание. Так воспроизведён конкретный пробел независимо от GUI и нагрузки.

В native fixture deadline сокращён до 1000 ms только для проверки механизма.
Это не публичная heartbeat-приёмка. Отдельные SDK/GUI тесты используют настоящий
срок 30000 ms, без подмены часов.

## Как устроено исправление

`StreamDecoderSource::decoderReader()` регистрирует только принадлежащие
декодеру readers через слабые ссылки. `StreamDecoderCursor` использует эту
регистрацию; обычный `source->reader()` сохраняет прежнее независимое владение.

`cancel()` по-прежнему меняет только atomic-флаг. Контроллер сначала публикует
ошибку/отмену, затем на своём worker вызывает `closeCancelledDecoderReaders()`.
Закрытие файла и запись receipt выполняются вне GUI-потока. Уже обнаруженная
ошибка доступна в snapshot контроллера до начала этого I/O; общий бюджет при
зависшем OS I/O этим не гарантируется.

Сам `Reader::close()` синхронизирован с выполняющимся чтением. Native handle
закрывается до записи `filesClosed`; удаление cache требует подтверждения
закрытия producer, исходников и всех readers. Сохранившийся cursor после этого
возвращает ошибку, не EOF, и не может открыть файл заново. Его поздний close
безопасен и повторяем.

Независимые readers не закрываются принудительно: они продолжают удерживать
кэш до явного закрытия владельцем. Подтверждённый complete без отмены также
не закрывает paused cursor из-за отсутствия heartbeat. Журнал регистрации
ограничен существующим лимитом readers самого store; новых потоков или
периодических таймеров не добавлено.

## Целевые проверки

`tests/progressive_continuous_decoder_retirement.py` проверяет четыре случая:

1. Callback остаётся жив, но после ошибки его файлы и lease освобождаются за 2 s.
2. Декодер освобождён, а независимый reader продолжает блокировать удаление кэша.
3. Заблокированное на новых данных чтение прерывается ошибкой; EOF не фиксируется.
4. Завершённый источник переживает срок heartbeat с открытым cursor.

Fixture-команды `decoderCursor`, `cursorWait` и другие существуют только в
тестовом CLI, не добавлены в публичный IPC плеера. Проверки используют настоящий
remux worker и реальные файлы/leases.

Два промежуточных отказа были ошибками нового теста: временный
`reader_registry_busy` ошибочно считался фатальным, а ожидающее чтение запускалось
до стабилизации output prefix. Оба отказа сохранены отдельно. Исправленный тест
повторно подтвердил отказ прежнего контроллера и успех новой реализации; бюджет
2 s не увеличивался. Native проверки успешны на Linux и Windows.

## Совместимость и границы

Qt использует общий код для Windows и Linux. Classic компилируется и проверяется
отдельно: его fragment reader сохраняет прежний raw-reader путь; принудительная
очистка независимых readers туда не переносилась. Изменения схем CLI/API,
capabilities и defaults не требуются. YouTubeHarvester не меняется.
