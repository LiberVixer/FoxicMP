# Optional audio: полная и частичная загрузка

[SDK 1.28](ProgressivePartialAudio.md) расширяет описанный ниже профиль SDK 1.25:
теперь доступна выбранная частичная дорожка с собственным буфером. Ниже сохранены
условия исходного полного профиля; актуальные capabilities и границы — в новом контракте.

Classic, Windows Qt и Linux Qt принимают необязательные аудиодорожки schema 2.
Пока такая дорожка скачивается, отсутствует или не имеет initialization, она
не открывается декодером и не уменьшает доступный буфер обязательного A/V.
YouTubeHarvester не меняется; Python API и schemaVersion остаются прежними.

## Объявление и готовность

Обязательны одно `required:true` video и хотя бы одно `required:true` audio.
Если указано default audio, оно тоже должно быть required. Всего до восьми
аудиодорожек, включая optional. Поддержаны прежние AAC-LC/Opus в fMP4 и
Opus/Vorbis в WebM с прежними ограничениями кодеков и локальных ресурсов.

Для дополнительной дорожки загрузчик объявляет `kind:audio`, `required:false`,
обычные source.resourceId, codecHint/containerHint, label/language.
Track/resource ID и имя файла сохраняются в последующих revision. Файл может
появиться позднее. Подключение происходит только после одновременного выполнения:

- track и resource имеют `state:complete`;
- `initializationReady:true`, length известна и положительна;
- ranges покрывают весь файл от нуля до length;
- действуют проверки владельца, локального пути, идентичности, ссылок и размера;
- фактические initialization и индекс пакетов соответствуют поддержанному профилю.

Запись всех байтов на диск без публикации ranges/complete не делает дорожку
доступной. Уже завершённый optional audio можно передать и в первом snapshot.
При готовности в разном порядке backend IDs могут отличаться от index в API:
Qt восстанавливает выбор после перемотки по стабильному URL ресурса.

## Воспроизведение и диагностика

`mediaTracks` сохраняет стабильные `id`/`index`, label/language и фактически
распознанный codec. Добавлены `required`, `ready`, `state`, `errorCode`, `error`:

| state | ready | Значение |
|---|---|---|
| waiting | false | Optional audio ещё не завершено; основное видео продолжает работать |
| ready | true | Initialization и полный индекс проверены; дорожка пригодна для подключения |
| error | false | Ошибка до подключения; дорожка исключена, A/V продолжает работать |

Активный status добавляет `loaded` и `selected`, сопоставленные с фактическими
дорожками декодера. `ready` само по себе не доказывает успешное декодирование.
Отказ позднего подключения сообщается через `backendErrorCode:decoder_error`
и `backendError`; он не превращается в корневую ошибку A/V.
В меню незавершённые/ошибочные дорожки видны как недоступные пункты.

Поздняя дорожка не выбирается автоматически. Classic останавливает граф для
изменения его связей, затем восстанавливает выбранный поток, позицию и состояние
воспроизведения. Qt выполняет отдельный audio-add; его асинхронный ответ привязан
к текущему источнику. Завершение обязательных дорожек позволяет досмотреть видео,
даже если optional audio не было готово. Для writer.state:complete загрузчик
должен перевести оставшиеся ресурсы в terminal state по общему контракту schema 2.

## Явные границы первого профиля

Capabilities исходного SDK 1.25 (история):

```json
{"audioTracksRequired":false,"optionalAudio":{"completeFileRequired":true,"lateCompletion":true,"pendingErrorIsolation":true,"activeResourceErrorsFatal":true,"requiredPrimaryAudio":true}}
```

Ошибки до активации изолируются, включая missing completed file, failed/cancelled,
неподдержанную фактическую initialization и испорченный индекс. Метаданные всего
snapshot, смена идентичности и отзыв опубликованных диапазонов остаются строгими.
Ошибка опубликованных байтов не исправляется подменой ресурса в той же дорожке.

После проверки и активации optional audio входит в прежнюю строгую A/V-модель:
повреждение или сокращение его опубликованных байтов может завершить весь сеанс,
включая случай невыбранной дорожки. Полная изоляция уже активного audio остаётся открытой; выбранная частичная
дорожка реализована отдельно в SDK 1.28.
Полное integrity-хеширование всех пакетов и реальная интеграция с Harvester
также остаются отдельными задачами.

Проверки: [отчёт трёх редакций](ProgressiveOptionalAudioValidation-2026-10-29.md).
Qt: CTest `progressive-optional-audio`. Classic:
`tests/windows/progressive_family_test.py --optional-audio-only` либо
`--optional-audio-profile NAME`, только в отдельной тестовой копии.

Главы и title из `metadata` обновляются отдельным revision и не требуют повторного открытия декодера; см. контракт metadata SDK 1.27 и исправления фактического UI.
