# Частично скачанная выбранная аудиодорожка — SDK 1.28

SDK 1.29 добавляет [изоляцию ошибок уже активной optional audio](ProgressiveActiveAudioErrors.md).
Приведённые ниже ограничения ошибок описывают исходный SDK 1.28.

Плеер принимает optional audio schema 2 до полной загрузки. Изменены Classic,
Windows Qt и Linux Qt. YouTubeHarvester не менялся; формат snapshot и Python API
совместимы с прежними версиями. Требуется новая сборка плеера, а не только SDK ZIP.

## Когда дорожка доступна

Сохраняются обязательные video и хотя бы одна required audio; default audio тоже
required. Дополнительная дорожка имеет `required:false`, стабильные ID/имя ресурса,
`initializationReady:true` и опубликованный непрерывный префикс от нуля.
Поддержаны AAC-LC/Opus в fMP4 и Opus/Vorbis в WebM с прежними ограничениями.

Плеер проверяет фактическую initialization и индекс подтверждённых пакетов.
Частичная дорожка становится ready при наличии не менее пяти секунд по индексу.
Это абсолютная граница готового начала дорожки, а не обещание пяти секунд впереди
текущей позиции. Завершённая короткая дорожка не требует пяти секунд; для complete
по-прежнему нужны известная положительная length и ranges полного файла.
До готовности decoder не открывается. Поздняя готовность подключает дорожку,
сохраняя текущий выбор. Неподтверждённые байты на диске не учитываются.

Файл дописывается без изменения уже опубликованных байтов и без подмены его
идентичности. После записи загрузчик публикует увеличенные ranges и revision.
Чтение на недокачанном конце ожидает данные и не выдаёт ложный EOF.

## Выбор и буферизация

Доступная граница — минимум required A/V и выбранной optional audio.
Невыбранные optional audio эту границу не уменьшают. Отключение звука исключает
optional из расчёта, но required audio сохраняют свою обязательность.
`availableSeconds` и `complete` активного status отражают этот расчёт.
`mediaTracks.ready` означает проверку источника; `loaded` и `selected` отражают
фактическое состояние backend.

Если выбранная дорожка отстаёт от текущего кадра, плеер ждёт данные на текущей
логической позиции. На конце доступного участка применяется прежняя буферизация:
пауза при запасе меньше секунды, возобновление при запасе не менее пяти секунд
или complete. Начальный запуск required A/V сохраняет десятисекундный буфер.
Во время ожидания можно вернуться на основную дорожку. Сохраняются пользовательская
пауза, выбор субтитров и идентичность сеанса/reader.

Qt заново открывает backend streams для смены аудио, прерывая блокирующие чтения,
и восстанавливает дорожки по стабильным путям. До готовности целевой позиции seek
остаётся pending; реальный decoder clock может временно показывать начало,
а timeline сохраняет seekTarget. Classic останавливает/flush граф, меняет
AudioSwitcher и восстанавливает позицию. Это может дать короткую паузу при выборе.
Если required A/V уже завершены, выбранная частичная audio всё равно сохраняет
проверку heartbeat загрузчика; его отсутствие не превращается в complete/EOF.

## Capabilities и границы

```json
{"optionalAudio":{"completeFileRequired":false,"selectedTrackBuffering":true,"minimumReadySeconds":5,"lateCompletion":true,"pendingErrorIsolation":true,"activeResourceErrorsFatal":true,"requiredPrimaryAudio":true}}
```

Это расширение готовности и выбранного буфера. После активации optional audio
по-прежнему входит в строгую модель A/V: повреждение или сокращение опубликованных
байтов может завершить весь сеанс, даже если дорожка не выбрана. Полная изоляция
ошибок активного audio и хеширование всех пакетов остаются отдельными задачами.
HLS/DASH timeline, live, универсальный demux/remux и реальные изменения Harvester
этот этап не реализует. Дисковые меню, оборудование и Wayland не проверяются.
