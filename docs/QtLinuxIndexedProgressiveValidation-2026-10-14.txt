Обычный MP4/M4A
==============
Добавлен индекс раздельных H.264 avc1 и AAC mp4a дорожек обычного fast-start MP4.
Нужны известная длина, полный moov перед mdat и первый подтверждённый пакет.
Метаданные в конце файла, изменения sample description и несколько дорожек
в одном файле не входят в этот progressive-режим.
Индекс учитывает stsz, stts, ctts, stss, stsc, stco/co64 и unit-rate edit list.
Парсер ограничивает размер moov, количество пакетов, размеры и границы данных.
Длительность при отсутствии duration100ns в manifest берётся из индекса видео.

Сверка с FFprobe на 20-секундных обычных MP4/M4A:
- 500 пакетов H.264 и 939 пакетов AAC;
- точное совпадение смещений, размеров и признаков ключевых кадров;
- DTS, PTS и длительность каждого пакета совпадают с допуском менее 2 мкс;
- edit list AAC и composition times H.264 учтены.
Это сверка времён пакетов, а не измерение физической синхронизации A/V.

Повреждённые stts/stco/stsz/stss/elst, неверный кодек и неполный первый пакет
отклоняются. Проверка неполного пакета подтверждает отсутствие чтения за
опубликованным префиксом.

Поведение плеера
===============
Одни сценарии выполняются отдельно для fMP4 и ordinary MP4:
ожидание на временной границе вместо EOF, отмена read, EOF только после complete,
декодирование двух дорожек одним libmpv, общая начальная буферизация,
seek в удержанном кэше, отказ за границей, ручная пауза, дописывание и Close.
Дополнительно проверены запуск/управление обычным MP4 без duration100ns.

Отдельный ordinary MP4 сценарий с остановкой записи на 60 секунд прошёл:
позиция не продвигается, ложного EOF нет, таймер интерфейса работает,
после дописывания сохраняется ручная пауза, затем просмотр возобновляется.
QtTest: 3 успешные проверки, 64,57 с (включая init/cleanup).

Полный локальный HTTP-путь проверен отдельно для fMP4 и ordinary MP4:
медленный HTTP → настоящий adapter → Linux provider → Qt → сборка FFmpeg.
Просмотр начинается до complete. Сервер получает ровно один GET на дорожку.
Итоговый файл собирается при активном плеере; исходные дорожки остаются доступны.
Сценарии используют отдельные папки, исключающие повторное использование
результата предыдущей загрузки.

Защита времени жизни
==================
Плеер запрашивает leaseAck и ждёт attached-подтверждения сохранённого lease
до открытия файлов. Без подтверждения источник не открывается.
Provider сверяет запрос с актуальной ревизией manifest, а не с прошлым heartbeat.
Ответ проверяется строгим JSON-парсером, включая уникальность полей и readerId.
Старые клиенты без leaseAck сохраняют прежнее поведение heartbeat.
Python-тест проверил свежую ревизию, запись lease до ответа и явное released.
Повторно прошли сценарии двух читателей, обрыва IPC, аварии, поддельного PID,
повторных полей, замены файлов и отказа второго provider.
