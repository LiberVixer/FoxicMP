Linux
Player использует тот же libmpv/Render API, что и программа.
Для 26 нормальных файлов проверяются распознанные дорожки, декодирование аудио,
вывод цветного кадра (кроме аудиофайлов), пауза, точный seek и естественный EOF.
Для трёх некорректных файлов — ошибка без ложного EOF и открытие исправного
источника в том же экземпляре Player. Отдельно проверяется сброс file-local
параметра seek при переходах MPEG-TS → MP4 → MPEG-PS → MKV.
Два запроса вывода: Software и OpenGL. В этой среде фактический вывод обоих
прогонов — Software; реальный OpenGL/GPU и HDR не подтверждены.

Исправление
Начальные испытания выявили seek на 1,25 с → 2,010022 с (MPEG-PS)
и 2,005333 с (MPEG-TS). После установки file-local
hr-seek-demuxer-offset=1 только для форматов mpeg/mpegts результат:
1,260022 с и 1,255333 с соответственно. Допуск теста 150 мс не менялся.
Для других контейнеров значение остаётся штатным, после смены файла сбрасывается.
В диагностике MPEG-PS/TS остаются предупреждения FFmpeg при переустановке
позиции (MP2 Header missing / H.264 reference POC); они включены в JSON.
PASS означает выполнение измеренных критериев, а не отсутствие предупреждений;
непрерывность аудиосигнала после seek отдельным захватом здесь не измерена.
Стоимость: при точной перемотке MPEG декодируется до секунды дополнительного
материала перед целью. Скорость перемотки на больших GOP требует отдельного измерения.
Документация механизма: https://mpv.io/manual/stable/#options-hr-seek-demuxer-offset

Classic Windows
Выполняется копия FoxicMP64 1.9.1.75 build 260920-1048 в отдельной папке.
Её INI выключает контекстное меню, регистрацию и историю, включает loopback Web API.
Работающий плеер пользователя не получает команд и не закрывается.
SSH-сеанс не предоставил обычный видеовывод; для сравнения используются
Null Video Renderer (Uncompressed) и Null Audio Renderer (Uncompressed).
Проверяются чтение тех же байтов, построение графа с декодированием, рост позиции
и длительность, а также отказ некорректных файлов. Это не проверка изображения,
физического звука, HDR, синхронизации или переключения дорожек Classic.
Каждый образец запускается отдельным процессом: первый вариант harness имел гонку
close/open и возвращал статус предыдущего файла; этот прогон не принят за результат.
Для синтетических образцов используются ASCII-псевдонимы, поэтому кириллические
пути Classic проверяются отдельно на пользовательском MKV через CLI.
Исходный INI Windows-плеера проверяется SHA-256 до/после.

Дополнительно проверен GUI/CLI/MPRIS с копией текущего Linux-профиля:
открытие с паузой на 60 с, перемотка 600 / 3179,294 / 6343,589 с с сохранением
паузы и последующее продолжение. Для изоляции отключены интеграция/web/трей,
звук приглушён, MPRIS включён на частной D-Bus; исходный INI не изменён.
Classic: открытие по исходному кириллическому пути и рост позиции в изолированном
headless-графе. Полный просмотр фильма и физический вывод не проверялись.
Кадры фильма не включаются в пакет или репозиторий: в отчёте только хеши.

Воспроизведение испытаний
python3 qt/tests/generate_media_matrix.py /каталог/корпуса
cmake --build /каталог/сборки --target foxicmp-media-matrix-tests -j3
python3 qt/tests/run_media_matrix.py --executable /каталог/сборки/foxicmp-media-matrix-tests --corpus /каталог/корпуса --reports /каталог/отчётов
Нужны действующий Qt-дисплей и аудиосервер. Windows:
qt/tests/run_classic_media_matrix.ps1 -SourceExe <exe> -Corpus <каталог> -ReportDirectory <новая папка> -HeadlessDecode
Опциональная проверка своего файла: FOXICMP_REAL_MEDIA=/путь/к/файлу;
передайте QtTest только realSource с FOXICMP_MATRIX_DIR и FOXICMP_MATRIX_REPORT.
