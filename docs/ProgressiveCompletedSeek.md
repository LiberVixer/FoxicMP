# SDK 1.56: перемотка после завершения загрузки

Общий результат для Linux Qt, Windows Qt и Windows Classic: пока progressive
сессия активна, после подтверждённого `writer.complete` можно переходить по
всему опубликованному ролику, сохраняя readerId, ручную паузу, скорость,
громкость, mute и выбор основной аудиодорожки.

Новая capability `completedSourceSeek` имеет `version=1`,
`mode=confirmed-complete-seek`, `scope=active-session`.
Она не расширяет допуск контейнеров/кодеков. Проверенный срез — H.264/AAC-LC:
обычные head/tail MP4 и отдельные fMP4 дорожки; дополнительно обе Qt проверены
с двумя legacy v1 MP4/M4A входами. Полная codec matrix остаётся в чеклисте.

## Поведение

У Qt источник, открытый недокачанным, мог сохранять потоковый режим декодера
и после `complete`. Для двух отдельных schema-2 fMP4 дорожек переход за пределы
packet cache отклонялся. Теперь полностью подтверждённые дорожки допускают
byte seek, а обычная команда перемотки переоткрывает декодер на том же
`ProgressiveSource`. Открытые файлы, проверенные ranges/SHA и reader lease
сохраняются. Путь исходника заново не открывается.

Прежний механизм reload сохраняет позицию назначения, ручную паузу, скорость
и выбор дорожек. Громкость/mute остаются параметрами того же проигрывателя.
Classic использует своё штатное позиционирование DirectShow по полному индексу.
Его страницы, оформление, клавиши, профиль и назначения команд не изменены.

Доступность полной перемотки наступает после подтверждения **всех обязательных
дорожек**, а не после роста физического файла. До `complete` продолжают действовать
прежние ограничения каждого профиля. Неподтверждённые байты не становятся
доступными из-за изменения способа seek.

Это перемотка через существующие элементы управления плеера: таймлайн,
клавиши и переходы к главам. Нового действия `seek` в downloader API нет.
Старые CLI/API и вызовы start/update/complete/status/release сохраняются.

## Наблюдение состояния

```python
caps = client.request({'version': 1, 'action': 'capabilities'})
seek = caps.get('completedSourceSeek', {})
state = client.command('status', session_id, readerId=reader_id)
if state.get('complete') and state.get('active'):
    controls = state.get('controls', {})
    # speed, volumePercent, muted — текущее состояние, не команда изменения.
```

`controls` добавлен в status активного плеера. Qt возвращает значения libmpv;
Classic — rate графа, пользовательскую громкость/mute и, когда доступно,
`nativeVolumeDbHundredths` из IBasicAudio. В подготовке/закрытии и после release
поля могут отсутствовать; наличие capability само по себе не означает playing.
Ручная пауза видна через `state=paused`.

`afterReleasedEof=false`: natural EOF по-прежнему закрывает reader и освобождает
файлы. Capability не обещает повторную перемотку уже освобождённой сессии и
не удерживает lease после окончания просмотра. Для нового просмотра требуется
новый start с новым reader по действующим правилам.

[Проверки](ProgressiveCompletedSeekValidation-2026-11-01.md) включают 90-секундные
источники, старт до complete, завершение на паузе, дальний переход вне кэша,
переходы вперёд/назад и реальный EOF/release. Пользовательские профили сохранены;
YouTubeHarvester не изменялся. Это ограниченный пункт общего ТЗ, не приёмка
всех форматов, live или длительной физической A/V-синхронизации.
