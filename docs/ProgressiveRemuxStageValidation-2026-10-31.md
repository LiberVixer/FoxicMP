# Проверка локального copy-remux — 31 октября 2026

SDK 1.52 / приложение 0.2.0. [Контракт](ProgressiveRemuxStage.md),
[JSON с точными exit codes и хешами](ProgressiveRemuxStageValidation-2026-10-31.json).
Пункт 2 чеклиста продвинут до ограниченного RAM stage; **новый playback adapter
и непрерывный remux всего ролика остаются незавершёнными**.

| Проверка | Linux Qt / GCC | Windows Qt / MinGW | Windows Classic / MSVC |
|---|---|---|---|
| Remux API плеера: 24 сценария | PASS | PASS | PASS |
| Native adapter: 24 сценария, выгрузка RAM для ffprobe | PASS | PASS | PASS |
| Worker: 10 сценариев с обычным завершением | PASS | PASS | PASS |
| Ранее работающие progressive-профили | H.264/Opus, VP9/Opus | H.264/Opus, VP9/Opus | AVC/HEVC/AV1/VP9 + AAC; v1 |

Окончательные Qt CTest-прогоны: **10/10, exit 0** на каждой ОС. В них включены
старые backend-demux, resource/segment и transport tests. API-тесты Qt дополнительно
проверяют отзывчивость UI и сохранение активной сессии. Classic — отдельная
интерактивная копия, с выключенной регистрацией контекстного меню до запуска.

Положительные входы: H.264/AAC stereo, H.264 с B-кадрами, video-only, audio-only
AAC 48 kHz mono и 44,1 kHz stereo, fractional 30000/1001, MOV, а также prefix
незавершённого восьмисекундного MP4. Подготовленный prefix ограничен 64 пакетами;
полные короткие входы помещаются в 128 пакетов.

На native adapter и прямом worker проверяются:

- число и SHA-256 сжатых пакетов по каждой дорожке — точное совпадение;
- PTS/DTS — совпадение с точностью до одного выходного tick;
- для полных положительных входов — точные хеши декодированных видео и PCM,
  включая AAC priming/end padding. Нет фильтров обрезки/ресэмплинга в сравнении;
- хеш выгруженного RAM buffer совпадает с опубликованным хешем;
- оригинальные bytes не меняются; stage/reader receipts освобождаются.

Проверены header/payload waiting, обновление ranges с retry, целостность SHA,
незаявленный физический хвост, sparse hole, cancel во время ожидания и после успеха,
forget, запрещённые input/output modes, неподдержанный MPEG-4 Part 2, шифрованный
вход, ненулевой start и неполная последовательность B-кадров. Такие ошибки не
выдают stage и не включают перекодирование.

ASan+UBSan: **24 native сценария и 10 прямых worker-сценариев — PASS, exit 0**;
transport — 8 PASS, exit 0. Для worker отдельно проверяются обычный выход и stderr,
чтобы аварийное завершение родителем не скрывало ошибки cleanup/LeakSanitizer.
Системный FFmpeg сам не пересобирался с sanitizers.
Python SDK: **20 unit tests на Linux и 20 на Windows, exit 0**.

Промежуточный fMP4-кандидат не прошёл сравнение звука на Windows: стандартный
fragmented mux/demux не сохранил AAC end padding. Он заменён обычным MP4 с
seekable AVIO в памяти и окончательным индексом. Исправлять контейнер собственным
парсером или ослаблять проверку decoded hashes в итоговой реализации не пришлось.
Первичные ошибки и исправления harness перечислены в JSON; итоговые прогоны — отдельно.

Linux EXE и worker обновлены атомарно по каждому файлу, оба прежних файла сохранены
для отката. Профиль и прочие файлы проверены по SHA-256. Просмотр не останавливался.
Штатный каталог integration автоматически не перезаписывался; новый SDK — в ZIP.
Windows-установки/их INI не менялись. HKCU-команды/иконки Classic проверены до/после;
одноразовая задача и временная копия удалены. Harvester, MPMY/MPC/MPC-BE, рабочий стол,
системный микшер, Wayland и отложенные аппаратные сценарии не затрагивались.

SDK ZIP содержит клиент/контракты/результаты. Новые установщики/EXE/DLL не публикуются
внутри SDK; установщики 0.2.0 этот этап не содержат. Остальное ТЗ остаётся в чеклисте.
