# Проверка подтверждённых данных — SDK 1.30

Linux Qt, Windows Qt и Classic используют один SHA-256 I/O-слой для ресурсов
schema 2. Изменения относятся только к плееру и его SDK; YouTubeHarvester не меняется.

## Контракт загрузчика

Необязательный `resources[].integrity` включает проверку всех подтверждённых
байтов конкретного ресурса. Старые снимки без этого поля сохраняют прежние проверки
идентичности, размера, initialization и последнего прочитанного участка.

```json
{
  "id": "audio",
  "name": "audio.part",
  "length": null,
  "ranges": [{"offset": "0", "length": "3"}],
  "state": "downloading",
  "integrity": {
    "algorithm": "sha256",
    "blocks": [{
      "offset": "0", "length": "3",
      "sha256": "ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad"
    }]
  }
}
```

Пример — три байта `abc`. Offset/length остаются точными каноническими десятичными
строками. SHA-256 — 64 строчных шестнадцатеричных символа. Блоки отсортированы,
не пересекаются, покрывают ровно все `ranges` и не включают неподтверждённые байты.
Допускаются пробелы между подтверждёнными диапазонами и пустой список для ещё
не появившегося ресурса. Максимум блока — 4 MiB, максимум списка — 4096 блоков.
Общий предел JSON в 65536 байтов сохраняется: на практике он ограничивает число
одновременно объявленных digest раньше, чем максимум списка. Это ограниченный
inline-контракт; внешний индекс контрольных сумм больших ресурсов пока не реализован.

Загрузчик сначала записывает и сбрасывает байты, затем публикует их диапазоны и
контрольные суммы. В следующих revision можно добавлять новые блоки, включая
заполнение прежних дыр. Уже опубликованные offset, length и digest неизменны;
замена/удаление, разделение старого блока и включение/отключение режима для
существующего ресурса запрещены. Короткий текущий блок не расширяется: следующий
блок начинается после него. Для изменения режима нужен новый ресурс/сеанс.

Проверять поддержку до отправки новых полей:

```json
{"integrity":{"algorithm":"sha256","maxBlockBytes":4194304,"maxBlocksPerResource":4096,"confirmedRangesCovered":true,"verifiedBeforeDecoder":true,"readChunkBytes":65536,"boundedReadAudit":true}}
```

Этот объект находится в `capabilities.schema2Playback.integrity`. Старый плеер
может отвергнуть неизвестное поле; SDK не должен молча удалять контрольные суммы.

## Чтение и ошибки

Перед первым возвратом байтов защищённого блока плеер читает весь блок небольшими
отменяемыми чтениями и сверяет его SHA-256 с опубликованным digest. Только после
совпадения сохраняет внутренние SHA-256 частей до 64 KiB. Повторное чтение
проверяет нужные части и копирует именно проверенные байты в буфер декодера.
Это обнаруживает и повреждение до первого чтения, и последующую перезапись;
частично проверенный результат не возвращается как успешный read.

Каждая обычная проверка pinned-файла дополнительно перепроверяет одну ранее
проверенную часть по кругу. Это ограниченный аудит прочитанного, а не обещание
мгновенной проверки всего файла при update. Непрочитанный блок проверяется при
первом обращении. Внутренние digest привязаны к pinned-дескриптору, не к имени;
переименование не переводит чтение на посторонний файл по прежнему пути.

Несовпадение даёт `integrity-mismatch`, обрезание — `source-truncated`; прежняя
проверка последнего чтения также может дать `source-rewritten`. Required-ресурс
завершает сеанс ошибкой. Optional audio изолируется по правилам SDK 1.29:
ошибочная дорожка недоступна до закрытия, выбранная переключается на primary.
Для SRT сохраняются правила изоляции optional subtitles. Ошибка структуры
снимка/изменение опубликованных digest отклоняют update до изменения состояния.

Проверка работает только для ресурсов с `integrity`. Без доверенного ожидаемого
digest нельзя установить, были ли исходные байты повреждены до первого чтения.
SHA-256 здесь проверяет соответствие данным writer; он не удостоверяет автора,
источник ролика или правильность исходного файла. Валидный digest также не
гарантирует поддержку кодека и не изолирует произвольный внутренний сбой декодера.

## Поставляемый helper

```python
from progressive_integrity import protect_snapshot
from progressive_v2 import V2PreviewSession

preview = V2PreviewSession(client, directory)
published = protect_snapshot(snapshot, directory)
preview.publish(published)
# После записи новых байтов и изменения snapshot/revision:
published = protect_snapshot(next_snapshot, directory, previous=published)
preview.publish(published)
```

Helper возвращает копию, считает только новые блоки, сохраняет прежние digest,
не переписывает медиа и не выполняет скачивание. По умолчанию блок — 256 KiB.
Хранить последний опубликованный результат обязательно: повторный расчёт всего
снимка без `previous` не должен переопределять ожидаемые digest активного сеанса.
Helper не заменяет полную проверку `validate`; он выполняется на стороне writer,
после записи данных, вне UI загрузчика. `V2PreviewSession` проверяет capability
до `start/update` защищённых ресурсов.

Тесты: `progressive-integrity-native`, `progressive-model`, `progressive-resources`,
`progressive-integrity` и четыре профиля `integrity-*-error` общего семейного стенда.
