# SDK 1.37: воспроизведение постраничного fMP4-каталога

Все три редакции используют общий путь `Fmp4V2Bridge`: Windows Classic,
Windows Qt и Linux Qt. Новый режим расширяет сегментный fMP4-профиль,
сохраняя прежний inline API и форматы SDK 1.36. Harvester не изменяется.

## Согласование перед запуском

Нужна новая сборка плеера. Установщики релиза 0.2.0 и прежние бинарники
не получают эту функцию при обновлении только Python SDK.
Проверяйте:

```python
caps = client.request({'version': 1, 'action': 'capabilities'})
segments = caps['schema2Playback']['segmentedPlayback']
assert segments.get('catalog', {}).get('mode') == 'paged-fmp4-v1'
```

Точную пару кодеков дополнительно проверяйте по `segments.profiles`.
Сохраняются H.264/HEVC/AV1/VP9 и AAC-LC/Opus прежних сегментных профилей.
Это две отдельные обязательные fMP4-дорожки VOD с постоянным codec/init,
известной длительностью, timebase 1/10000000, без discontinuity/offset rebasing.
Muxed A/V, WebM/TS-сегменты, live, смена конфигурации, дополнительные audio/SRT
этим профилем не включаются. Обычные отдельные multi-audio/SRT профили остаются.

## Что публикует загрузчик

Используйте [формат каталога](ProgressiveSegmentCatalog.md): основной JSON
с `segmentCatalog`, отдельные неизменяемые UTF-8 страницы и локальные init/media.
Каждый дескриптор страницы содержит точную строковую длину и SHA-256.
Страницы хранят только полные, подтверждённые, non-retired ресурсы;
неопубликованное будущее можно добавлять следующими страницами/inline-хвостом.

**SHA-256 `resources[].integrity` обязателен для всех ресурсов этого режима**,
включая init, inline-хвост и архивированные медиа. SHA страницы не заменяет
SHA медиа. Helper `protect_snapshot` можно применять к раскрытому описанию
после записи/flush медиа, затем сериализовать ресурсы/сегменты в страницы.
Не применяйте его только к корневому inline-хвосту, пропуская архивированные ресурсы.

Пределы: основной JSON/полный RPC не больше 65536 байт, до 128 страниц по
65536 байт, до 8192 раскрытых ресурсов, до 4096 сегментов на дорожку.
Известная длина/подтверждённые диапазоны медиа — до 16 MiB, init — до 1 MiB.
Индекс backend также сохраняет прежний предел 2 000 000 samples на дорожку.
Это ограниченный профиль, не обещание неограниченной длины ролика.

Корень и отдельная страница сохраняют структурный предел 128 элементов в массиве,
включая `integrity.blocks`. Для ресурсов до 16 MiB подходит стандартный размер
SHA-блока helper — 256 KiB (до 64 блоков). Более общий предел I/O в 4096 блоков
не отменяет ограничений внешней JSON-страницы. Все пределы действуют совместно;
при крупных описаниях кладите меньше ресурсов в одну страницу.

Опубликованный дескриптор страницы и её байты не меняются. Добавляйте новые
страницы; полный опубликованный inline-хвост можно переместить в новую страницу
без изменения идентичности ресурсов/сегментов. Сохраняйте старые страницы
и имена файлов. Writer не скачивает данные через плеер: URL/HLS/DASH запросы
и приоритизация загрузки остаются у загрузчика.

## Проверка, запуск и обновление

`validate` остаётся **чистой inline-проверкой**, без filesystem I/O; каталог
он не раскрывает. Для каталога используйте `probe` с `sessionDirectory`,
затем прежние `start` / `update` / `complete`:

```python
from progressive_v2 import V2PreviewSession

probe = client.probe(catalog_root, session_directory)
# supported=true — профиль/подтверждённый префикс готов; это ещё не playing.
preview = V2PreviewSession(client, str(session_directory), title=title)
result = preview.publish(catalog_root)
# Дальше публикуйте новые revision и наблюдайте preview.heartbeat()/status().
```

SDK откажет старому плееру **до** start/изменения состояния клиента, если нет
отдельной capability каталога. Он отправляет корень и не читает страницы сам:
это делает плеер в worker. В UI выполняется только admission ограниченного
JSON; фактическая проверка профиля следует после чтения страниц.

Новая отсутствующая страница даёт `waiting-index`, `requiresCompleteFile=false`
в отрицательном probe; ориентируйтесь на `reasonCode`, а не общий legacy `mode`.
SDK `publish` до первого start возвращает `state=waiting-index`, не помечая start
неопределённым. После появления страницы запрос можно повторить.
`missing-index` означает исчезновение уже принятой страницы; `source-replaced`
и `integrity-mismatch` — подмену/повреждение. Не подменяйте эти причины EOF.

Обновления каталога готовятся без mutex backend/status. Только после проверки
страниц и модели происходит публикация в источник. Неуспешная новая страница
не меняет последнюю принятую revision/привязки и не закрывает прежний поток.
Для нового режима Qt/Classic сохраняют точные машинные коды ошибки update;
прежний inline-профиль сохраняет совместимый `invalid_update`.
Ошибка уже принятых **медиа-байтов** остаётся ошибкой required-источника.

## Leases, перемотка и удаление

[Медиа-кэш](ProgressiveCatalogCache.md) держит не больше восьми открытых файлов.
При возврате к старому сегменту проверяются идентичность и затронутые SHA-блоки.
Виртуальные offsets и индекс сохраняются при добавлении страниц; source/главный
reader ID остаются теми же при паузе, update и seek.

**Сохраняйте все опубликованные страницы и медиа до release главного reader ID,
полученного от start.** Его можно безопасно обслуживать через
`V2PreviewSession.close()` / reader release acknowledgement. Это отражено
`retainAllPublishedResourcesUntilRelease=true` в capability.
Отсутствие/забывание внутренней resource-lease не разрешает удаление:
LRU закрыл файл сейчас, но плеер ещё может перемотать к нему. Не делайте вывод
о завершении всей сессии по неизвестному resource reader ID.
Если те же файлы используют другие preview/probe readers, дождитесь release
каждого из них: квитанция главного reader подтверждает закрытие его владельца,
а не независимых читателей в других профилях/редакциях.

## Что реально проверено

[Отчёт трёх редакций](ProgressiveCatalogPlaybackValidation-2026-10-30.md):
90-секундные синтетические записи H.264/AAC, HEVC Main10/Opus stereo и
AV1 Main10/AAC. Каталоги растут от 42–43 до 182–183 ресурсов, воспроизводятся
до конца загрузки, сохраняют паузу, перемотку вперёд/назад, переживают недоступную
новую страницу и повторно открываются после полного release. Обе Qt-сборки
проверяют меняющиеся кадры после seek, codec/pixelformat и декодированное аудио.
Classic проходит реальные графы с навигацией по опубликованным главам.

22 native-сценария дополнительно сравнивают байты всех 15 сочетаний кодеков
и отказы. Поддержка модели до 8192 ресурсов не является playback-тестом
8192 реальных файлов. Многочасовые записи, медленные диски, реальные загрузчики
и измерение длительной A/V sync остаются отдельной приёмкой.

Подготовка/обновление индексируют подтверждённый префикс. Для большого уже
готового каталога это может превысить существующий deadline подготовки;
ленивый/постраничный индекс backend ещё не реализован. Время зависшего syscall
или ожидания registry guard не ограничено этим профилем. Прежние ограничения
GPU retirement и обычных Classic-графов также не объявляются решёнными.

SDK-архив содержит клиент/документацию; новые EXE/установщики в него не входят.
Исходники трёх приложений доступны в соответствующем git tag проекта.
