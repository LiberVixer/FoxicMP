# Обновление legacy-сеанса без файлового I/O под UI-блокировкой

SDK 1.11, общий Qt-код Linux/Windows и Windows Classic. YouTubeHarvester не
изменяется. CLI/provider и SDK wire-контракты прежние; новые кодеки не добавлены.

## Что изменилось

Linux Qt читает manifest, проверяет привязанные файлы и доиндексирует подтверждённый
префикс в существующем worker, не удерживая metadata mutex интерфейса. Сначала
готовится новый результат, затем snapshot и duration/available/complete применяются
вместе под короткой блокировкой. Пока идёт файловая работа, UI видит прежнюю
доступную границу. Сам индекс принадлежит worker; UI/decoder используют опубликованный
снимок и подтверждённый префикс, не читают изменяемый объект индексатора.

Windows Qt сохраняет фоновый publish-путь и дополнительно выносит периодическую
проверку открытых файлов из metadata mutex. Связь с provider/heartbeat уже выполнялась
в worker. UI notify лишь меняет желаемое playback-состояние под короткой блокировкой.

Classic проверяет физический размер вне metadata mutex. Новая копия fragment index
строится до commit; snapshot, fragment indexes и duration заменяются вместе.
Раньше manifest revision могла стать видимой до окончания индексации. Старые
shared indexes освобождаются после выхода из блокировки. Начальный open по-прежнему
использует подготовку из [SDK 1.10](ProgressiveLegacyOpening.md).

Проверки файлов выполняются и без новой ревизии manifest. Для старой/повторной
ревизии используется последняя принятая граница, чтобы устаревший меньший префикс
не скрывал усечение. Изменение файлов не превращается в успешный EOF/complete.
Полная криптографическая проверка содержимого этим не заменяется.

Stop/Close не применяют результат отменённой доиндексации. Ошибка чтения, вызванная
отменой этой работы, не выдаётся как новая ошибка повреждения медиа. В Classic
Stop дополнительно разрешён для progressive-сеанса на стадии MLS_LOADING, когда
ещё нет обычного состояния воспроизведения DirectShow. Иначе UI мог отключать
команду до входа в уже существующий обработчик отмены.

```json
{
  "legacyRefresh": {
    "fileIoOutsideMetadataLock": true,
    "snapshotIndexCommitAtomic": true,
    "notificationsMetadataOnly": true
  }
}
```

Это описание конкретного maintenance-пути. Notify и раньше не выполнял файловые
операции: сохраняется прежняя модель уведомлений через worker.
Новых worker, periodic automations или вмешательства в пользовательский сеанс нет.
Существующие собственные циклы обслуживания плеера сохраняются.

## Отмена, release и ограничения

Объект Source и дескрипторы остаются живы до завершения реального I/O и последнего
читателя. Используется прежний [SourceRetirement](ProgressiveRetirement.md), release
следует после закрытия файлов, не по timeout/Stop. Неполный файл не считается
докачанным из-за приостановленного worker или отсутствия новой revision.

Внутренние синхронные Source-вызовы сохраняют свой смысл. Native open/read/stat
не прерываются принудительно. Renderer/DirectShow graph shutdown, CPU/память больших
индексов, часть прочих CLI/GUI файловых операций и глобальная задержка закрытия ещё
не квалифицированы. Полный F-01 и codec/live/remux-матрица остаются в
[плане](ProgressiveIntegrationPlan.md). Эти изменения не являются новой версией
публичных установщиков 0.2.0.
[Проверки трёх редакций](ProgressiveLegacyMaintenanceValidation-2026-10-26.md).
